## 3. Technical Attribution Architecture

### 3.1 Outbound Request Specification
Every request dispatched by `agentflight.providers.openany.OpenAnyProvider` to an OpenAny domain (`*.openany.si` or configured `base_url`/`mcp_url`) MUST include:

```http
POST /v1/chat/completions HTTP/1.1
Host: api.openany.si
Authorization: Bearer ale-your-openany-api-key
Content-Type: application/json
Accept: application/json, text/event-stream
User-Agent: agentflight/1.2.0 (partner=openany; https://github.com/codesphere-u/agentflight)
X-OpenAny-Partner-Id: agentflight
```

### 3.2 Security & Domain Boundary Isolation
To protect user credentials and prevent unauthorized attribution leakage:
- `X-OpenAny-Partner-Id` and `Authorization` headers are **strictly gated** by `is_openany_domain(target_url)`.
- If a developer configures a custom third-party endpoint (e.g. OpenAI, Anthropic, or an internal proxy), `X-OpenAny-Partner-Id` and OpenAny API keys are **never transmitted**.
- Replay operations via `CassetteReplayer` run completely offline with **zero network transmissions** and **zero header egress**.

## 6. Open-Source Principles & Provider Agnosticism

AgentFlight's commercial partnership with OpenAny operates strictly within our open-source ethos:
- **100% Provider-Agnostic:** AgentFlight remains completely open, modular, and vendor-neutral. Developers are never forced to use OpenAny.
